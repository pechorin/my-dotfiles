# Мои dotfile'ы

Мои настройки для macOS: Zsh, Git, Neovim и всё, что нужно рядом с ними. Языки, утилиты, приложения и шрифты собраны в [mise.toml](mise.toml), чтобы не вспоминать по одному, что ставить на новую машину.

Конфиги переехали сюда из `home-files` и `vim-files`. Местами ещё остались старые пути и эксперименты — особенно в Neovim.

## Что где лежит

- [mise.toml](mise.toml) — версии языков, пакеты Homebrew, переменные окружения и симлинки.
- [.zprofile](.zprofile) — Homebrew, пути и подключение секретов.
- [.zshrc](.zshrc) — mise, автодополнение, плагины и алиасы. Например, `be` вместо `bundle exec`.
- [.zsh_plugins.txt](.zsh_plugins.txt) — плагины Zsh для Antidote.
- [.gitconfig](.gitconfig) — Git LFS, delta, rebase при pull и прочие настройки Git.
- [vim/](vim/) — конфигурация Neovim. Название каталога осталось историческое; обычный Vim этот конфиг не загружает.

## Окружение

В mise описаны Node LTS, Go и Rust, а также языковые серверы и форматтеры для редактора. Версии для отдельных проектов можно задавать в их конфигах.

Ruby управляется через rbenv: mise устанавливает `rbenv` и `ruby-build` как пакеты Homebrew, а Zsh подключает rbenv. Управление Ruby в mise отключено. rbenv использует установки из `~/.rbenv/versions`, глобальную версию из `~/.rbenv/version` и проектные `.ruby-version`.

Чтобы установить менеджер и сборщик отдельно от остальных пакетов:

```sh
mise bootstrap packages apply brew:rbenv brew:ruby-build
```

На новой машине Ruby нужно установить отдельно, например `rbenv install -s 3.4.7`, и выбрать по умолчанию через `rbenv global 3.4.7`. Для проекта установи версию из его `.ruby-version`. После установки гемов с исполняемыми файлами при необходимости выполни `rbenv rehash`.

Python управляется через pyenv: mise устанавливает пакет Homebrew, `.zprofile` добавляет shims для login-shell, а `.zshrc` инициализирует pyenv для интерактивных сессий. Управление Python в mise отключено. pyenv использует установки из `~/.pyenv/versions` (или `$PYENV_ROOT/versions`), глобальную версию и проектные `.python-version`.

Чтобы установить pyenv отдельно:

```sh
mise bootstrap packages apply brew:pyenv
```

Версии Python устанавливаются через `pyenv install <версия>`, версия по умолчанию выбирается через `pyenv global <версия>`, а для проекта — через `pyenv local <версия>`. После установки пакетов с исполняемыми файлами при необходимости выполни `pyenv rehash`.

Пакеты Homebrew лежат в том же файле, в `[bootstrap.packages]`: от `ripgrep`, `fzf` и `jq` до Docker, баз данных и приложений для macOS. Там же — Nerd Fonts: Iosevka, JetBrains Mono, Fira Code и ещё несколько семейств. Шрифт в терминале нужно выбрать отдельно.

Большинство версий оставлено как `latest`, `lts` или `stable`, lockfile пока нет. Автоматическая установка недостающих инструментов выключена через `auto_install = false`.

## Подключение на другой машине

Конфигурация рассчитана на macOS с Homebrew в `/opt/homebrew`. Установка пакетов и ссылки на dotfiles описаны в mise; отдельного `install.sh` здесь нет.

Перед подключением стоит пройтись по нескольким местам:

1. В `.zprofile` и `.zshrc` переменная `MISE_GLOBAL_CONFIG_FILE` указывает на `~/my-dotfiles/mise.toml`. Если репозиторий лежит в другом каталоге, путь нужно поменять. Если уже есть глобальный конфиг mise, его настройки тоже стоит учесть.
2. В `.gitconfig` лежат мои настройки Git, а в `[env]` — личные пути. Их лучше сразу подправить под себя.
3. Секреты читаются из `~/.secrets/`. В репозитории их нет.
4. Перед созданием симлинков нужно сохранить свои dotfiles. Список ссылок находится в `[dotfiles]`: Zsh, Git, `.vimrc`, `.ctags`, точка входа Neovim и две цветовые схемы. Каталог `~/.vim` целиком не заменяется.

Для Neovim отдельно понадобятся vim-plug, плагины из `:PlugInstall` и Tree-sitter CLI 0.26.1+. После установки плагинов запусти `:TSInstallConfigured` для установки парсеров. В headless-режиме `nvim --headless '+TSInstallConfigured!' +qa` дождётся завершения установки. При обновлении nvim-treesitter vim-plug вызывает `:TSUpdate`. Полная установка с нуля пока не проверена.

## Neovim

Здесь тема Adwaita, поиск через fzf-lua, Neo-tree, Fugitive и Gitsigns. Для переходов между кодом и тестами есть other.nvim, для форматирования — Conform. Плагинов запуска тестов нет.

Конфиг начинается с `vim/init.vim`, который подключает `~/.vimrc`. Дальше `00_init.lua` загружает номерные файлы из `vim/` по порядку. Если нужно что-то поменять, основные места такие:

| Что поменять | Файл в `vim/` |
| --- | --- |
| Плагины | [01_bundle.vim](vim/01_bundle.vim) |
| Отступы, поиск и поведение редактора | [02_options.vim](vim/02_options.vim) |
| Leader и глобальные настройки плагинов | [03_globals.vim](vim/03_globals.vim) |
| Тему | [04_colorscheme.lua](vim/04_colorscheme.lua) |
| Автокоманды | [05_autocommands.vim](vim/05_autocommands.vim) |
| Сочетания клавиш | [06_mappings.lua](vim/06_mappings.lua) |
| Настройки плагинов и форматирование | [07_plugins.lua](vim/07_plugins.lua) |

### Клавиши, которые легко забыть

Leader — запятая, поэтому `<leader>ff` — это `,ff`.

| Клавиши | Действие |
| --- | --- |
| `;` | Ввод команды вместо `:` |
| `,ff` или `,q` | Найти файл |
| `,b` | Найти открытый буфер |
| `,fa` | Все команды поиска fzf-lua |
| `,rr`, `,rh` | Недавно открытые файлы |
| `,sc` | История Git-коммитов через fzf-lua |
| `,gS` | Поиск и замена через GrugFar |
| `,m`, `,M` | Neo-tree для проекта или текущего файла |
| `,,`, `,.` | Буферы и Git status в Neo-tree |
| `,w` | Подсказки WhichKey |
| `,c` | Закомментировать строку или выделение |
| `,gg`, `,gG`, `,gb` | Fugitive во вкладке, в окне, Git blame |
| `,ll`, `,lt` | Перейти к связанному файлу или тесту |
| `,co`, `,cc` | Открыть или закрыть quickfix |
| `,ec` | Выбрать цветовую схему |
| `,eb` | Открыть `~/.vimrc` |
| `K` | Документация под курсором |
| `Shift-Right`, `Shift-Left` | Следующая или предыдущая вкладка |
| `Q`, `Z` | Закрыть вкладку или удалить буфер |

`:Format` форматирует буфер или выделение. Для Python используются isort и black, для Lua — stylua, для JavaScript — prettierd или prettier, для Rust — rustfmt. У Go форматирование настроено через go.nvim и gopls. Полное форматирование вызывается отдельно.

При сохранении хвостовые пробелы убираются только у обычных редактируемых исходников из списка в `05_autocommands.vim`. Markdown, текст, YAML, шаблоны, каталоги `fixture(s)`, `testdata`, `snapshot(s)` и `__snapshots__` сохраняются без такой очистки. Для отдельного буфера очистку можно отключить через `:let b:trim_trailing_whitespace = 0`.

LSP подключается через `vim.lsp.config` и `vim.lsp.enable`; настройки серверов поставляет nvim-lspconfig. Общие клавиши устанавливаются через `LspAttach`, включая Python. Списки code actions используют fzf-lua через `vim.ui.select`.

Подсветка использует Tree-sitter; JS/TS/JSX/TSX также используют его отступы. Для Jinja сохранён один `vim-jinja`: в текущих Tree-sitter queries нет правил отступов Jinja. Файлы `.j2` и `.jinja2` распознаются как Jinja; правило для `*.yml.j2` сохраняет YAML.

`,c` вызывает встроенные `gcc`/`gc`, включая визуальное выделение. Комментарий определяется контекстом Tree-sitter: в JSX это `{/* ... */}`, в HTML-части ERB — `<!-- ... -->`, внутри многострочного Ruby-блока — `# ...`. HTML-комментарий вокруг `<%= ... %>` не отключает исполнение Ruby: такие ERB-теги нужно комментировать на уровне шаблона.

После установки парсеров проверки конфигурации можно запустить из корня репозитория:

```sh
nvim --headless -i NONE '+luafile vim/tests/smoke.lua' +qa!
```

Оставшиеся рекомендации записаны в [audit.md](audit.md). Большинство плагинов пока не закреплено на конкретных коммитах.
